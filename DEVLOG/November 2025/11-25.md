###### *What problems did I run into? Even small frustrations are worth noting.*

  * At first I tried using tuples which DID work but when the data made it back to the client the objects variables didn't have any names, and I want them to have names so its obvious to anyone taking a glace at the data what it represents.
  * So I learned you can use a weak "Object" type in C# to basically allow me to add whatever I want to the list as an object without needing to declare a separate class and cluttering up my code.
    * This does mean i'll need to be super careful if I want to use that function anywhere else though.

## Learnings & Key Takeaways

###### *What did I learn today? Could be a new skill, trick, process, or even a fun fact!*

* You can use the Object keyword in C# to use weak typing like in JavaScript or python!
* SignalR syntax: InvokeAsync vs SendAsync
  * SendAsync does not wait for a response from the client/server 
    * ideal in most instances with SignalR since it's more inline with what Websockets are good for
  * InvokeAsync DOES wait for a response from the client/server
    * Must be used when expecting some kind of return value from the server, like when the client is invoking "RequestServerData" in SageXR
